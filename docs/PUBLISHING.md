# 公開・配布前の確認

このリポジトリは制作実績の閲覧と localhost デモを目的とします。ここに記載する確認は公開用リポジトリの検査手順です。本番サービスの公開や運用完了を示すものではありません。

## ローカル確認

1. Node.js 22.18 以上を用意します。
2. 依存関係を固定ファイルからインストールします: `npm ci`
3. 架空デモデータを初期化します: `npm run demo:setup`
4. 開発サーバーを起動します: `npm run dev`
5. `http://127.0.0.1:3000` と `/demo?role=admin`、`/demo?role=member` を確認します。
6. アプリが localhost 以外からのアクセスを拒否し、メール送信・決済Webhook・Cronがデモで動かないことを確認します。
7. `npm run check` を実行します。23件のロジックテスト、7件の画面ソース検査、lint、型確認、ビルドが順に含まれます。

`demo:setup` は繰り返し実行できる初期化処理で、既存データを一括削除しません。デモに個人情報や本番データを入力しないでください。

## GitHub Actions

`.github/workflows/checks.yml` は Semgrep による静的解析、Gitleaks による秘密情報検査、品質チェックを実行します。後続の required ジョブは3つすべてが成功したときだけ成功します。このワークフローにはデプロイジョブがありません。

## GitHub に公開する前

- 元の開発フォルダーや Git 履歴を含めず、公開対象として確認したファイルだけを新しいリポジトリに登録します。
- `.env`、認証情報、実利用者情報、実DBの書き出し、ログ、ビルド生成物が含まれていないことを確認します。
- GitHub Actions の Semgrep、Gitleaks、品質チェックが実行され、required ジョブが成功することを確認します。
- `docs/screenshots/` の画像が配置され、架空データだけを表示し、画面説明と一致していることを確認します。
- 公開時のライセンス方針を確認します。現時点では、ソースコードの再利用・再配布を許可するライセンスは設定していません。
- 公開後、README の手順を新しい作業環境で再現してから、制作実績ページ等への掲載を判断します。

## 実運用への移行

実運用には、本番用Cloudflare環境とDB、認証・権限の確認、秘密情報の安全な登録、メールや決済サービスの設定、Webhook署名検証、Cronの運用、個人情報の保存期間・問い合わせ対応・障害時手順の整備が必要です。これらはローカルデモの公開とは別の作業であり、このリポジトリのデモ起動だけでは有効になりません。
