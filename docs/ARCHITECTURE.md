# アーキテクチャ概要

## 全体構成

アプリは React / TypeScript のページとサーバー側の Route Handler で構成されます。vinext が Next.js 互換のルーティングを Vite 上で動かし、Cloudflare 向けの実行時には Worker から D1 データベースへ接続します。Drizzle ORM と SQL マイグレーションでテーブル構造を管理します。

```text
ブラウザー
  └─ Reactページ・操作フォーム
       └─ Route Handler（入力確認・権限確認・予約処理）
            └─ D1（予約、会員、回数、操作履歴）
```

ローカル公開デモでは、localhost 制限付きのデモ用データ環境を使います。実環境の認証情報や本番DBへ接続する構成ではありません。

## 主な画面

- `/`: 教室の紹介と無料体験への導線
- `/trial`: 無料体験の申し込み
- `/trial/manage/[reference]`: 体験予約の確認・変更・キャンセル
- `/member`: 会員の予約と残り回数
- `/member/book`: 会員レッスン予約
- `/admin`: 教室側の概要
- `/admin/calendar`: 体験、会員予約、予約不可時間をまとめたカレンダー

## 予約データの扱い

予約処理は入力内容を検査した後、対象者の権限、利用可能なレッスン回数、予約枠の競合を確認します。枠の重複はアプリケーションの確認に加えてDBの一意制約で防ぐ設計です。予約済み枠を同時に複数人が選んだ場合は、後続の処理に競合として応答し、別の空き枠を選び直せるようにします。

会員の月内回数は付与数から予約中・受講済み・失効等を差し引いて求めます。振替枠は通常の月次回数と区別して扱います。体験予約・会員予約の状態変更は、予約イベントや管理操作ログに記録するデータ構造です。

## デモで有効な範囲

デモでは架空データを使用し、role query parameter によって管理者または会員表示を切り替えます。デモのセットアップ処理は不足データを追加する冪等な初期化で、DB全体の削除は行いません。アクセスは localhost に制限され、実メール送信、決済Webhook、Cron処理は止めています。

このデモで保存される予約は架空DB上の表示確認用です。インターネット公開、実顧客データの保存、実際の通知・課金には使えません。

## ディレクトリの役割

- `app/`: 画面、共通UI、API Route Handler
- `lib/`: 予約・認証・回数計算などの処理
- `db/` と `drizzle/`: DB接続、スキーマ、マイグレーション
- `worker/`: Cloudflare Worker のエントリ
- `tests/`: 予約・DBなどの自動テスト
- `docs/`: 制作説明と公開手順
